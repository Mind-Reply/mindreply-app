# Estate Naming Matrix

Names are intentionally not reused across every repository. Each surface gets a vocabulary that describes its job.

| Repository | Surface name | Core job | Preferred verbs |
|---|---|---|---|
| mind-reply-core | **Proofline** | canonical product/runtime | verify, reconcile, deliver |
| agent-control-plane | **Crownline** | owner operations | observe, approve, release |
| a11k-surface | **Dialogue Atlas** | owner conversation | ask, retrieve, decide |
| saas-starter | **Human Moment** | reusable product starter | start, carry, recover |
| nexus-core | **Quiet Routing** | intent routing | route, ground, hand back |
| forge | **Foundry** | artifact construction | mold, inspect, stamp |
| brushworks | **Studio** | interface craft | compose, focus, breathe |
| mr | **People Operations** | practical user work | reply, follow up, close |
| mindreply | **ReplyRail** | communication product | receive, prepare, send |
| own | **Private Atlas** | owner/personal context | reflect, preserve, choose |

## Integration vocabulary

- n8n -> **Relay Loom** when discussing the capability.
- Vector retrieval -> **Memory Well** when discussing the user experience.
- Zapier -> **Switchboard** when discussing simple cross-app delivery.
- GitHub Actions -> **Clockwork** when discussing scheduled checks.
- Sentry -> **Witness** when discussing error evidence.

Implementation manifests may use vendor names. Product language should describe the behavior.

## Non-negotiable

A unique name is justified only if it changes recognition, behavior or ownership. Do not rename ordinary things merely to look novel.
