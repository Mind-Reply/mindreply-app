# Sovereign moats — controlled execution plan

## Objective

Expand MindReply beyond a conventional cloud wrapper through defensible,
privacy-preserving software and carefully diligenced physical infrastructure.
Quiet execution means confidentiality and disciplined disclosure—not deception,
evasion, hidden ownership, untraceable routing, or regulatory avoidance.

## Priority order

### 1. On-device Core ML enclave — execute now

- Deliver a local-only inference package with no network or telemetry dependency.
- Benchmark on owned Apple hardware before making privacy or performance claims.
- Keep model provenance, licences, conversion settings, and hashes auditable.
- Gate Secure Enclave signing behind a reviewed threat model.

**Acceptance:** reproducible model conversion; offline test evidence; documented
latency, memory, energy and quality; no outbound traffic in failure paths.

### 2. Engine isolation — execute now

- Separate Profit, Message Refiner, Assistant, and Mail into distinct identities,
  secrets, storage and deployment boundaries.
- Default-deny cross-engine communication.
- Never mirror mail, personal data, or production prompts into a shadow system
  without purpose limitation, minimisation, and valid authorization.

**Acceptance:** an identity compromised in one engine cannot read another
engine's secrets or data; every allowed route is documented and logged.

### 3. Public endpoint and deployment integrity — execute now

- Treat DNS, TLS, deployment, and health evidence as release requirements.
- Health endpoints report only facts the process can prove.
- A release is not “live” until DNS resolves, TLS validates, the expected commit
  is returned, and the checkout path is verified independently.

**Acceptance:** canonical domains resolve; HTTPS succeeds; health reports the
expected immutable commit; rollback is documented and tested.

### 4. Atmospheric sensor pilot — research, then one-unit test

- Start with one legally placed sensor on property controlled by or expressly
  consenting to the pilot.
- Collect only environmental measurements necessary for the stated purpose.
- Validate calibration, uptime, provenance, hosting consent, and commercial data
  rights before scaling.

**Acceptance:** written host permission; calibration evidence; data dictionary;
retention policy; lawful marketplace use; no covert personal or occupancy
inference.

### 5. Edge facilities and property rights — diligence only

- Use public registries and licensed professional advice to assess grid capacity,
  title, zoning, environmental liabilities, heritage restrictions, telecom
  permissions, aviation rules and total capital exposure.
- Do not contact owners through concealed identities, proxy entities used to
  mislead, or pressure tactics.
- Do not acquire property, spectrum, air rights, corridors, certificates,
  trademarks, minerals, offsets, or regulated assets without verified title,
  beneficial-ownership disclosure, sanctions checks, valuation, and specialist
  legal/tax review.

**Acceptance before any offer:** verified seller authority; independent title and
regulatory report; total-cost model; environmental and security assessment;
written investment ceiling; exit scenario.

|---|---|---|
| 1–2 | Engineering | Pin model candidate, licence and conversion environment |
| 3–4 | Engineering | Convert model and produce deterministic hashes |
| 5–6 | Security | Test offline behavior and enumerate outbound-capable dependencies |
| 7 | Product | Define one bounded HNW/enterprise use case without sensitive-data expansion |
| 8–9 | Platform | Map four engine identities, secrets, stores and allowed routes |
| 10–11 | Platform | Implement default-deny policy in a non-production environment |
| 12 | Operations | Run DNS/TLS/health release check for canonical domains |
| 13 | Governance | Review privacy claims, model licence, audit evidence and rollback |
| 14 | Owner | Decide continue, revise, or stop against written acceptance criteria |

## Hard prohibitions

- No exposed credentials, committed production environments, or copied secrets.
- No “untraceable” communications, surveillance evasion, sanctions avoidance,
  hidden beneficial ownership, misleading proxy outreach, or deceptive identity.
- No training on private mail or messages without explicit authorization,
  minimisation, retention limits, and an approved purpose.
- No claims that output is indistinguishable from a human; preserve style only
  with consent, attribution, and human approval for consequential messages.
- No autonomous physical purchases, bookings, filings, or legal commitments.
