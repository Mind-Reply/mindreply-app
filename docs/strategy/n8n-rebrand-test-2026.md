# n8n Rebrand Test & Activation Charter — 2026-09

## Operating role

A11pro treats the proposed n8n rebrand as a controlled product/brand experiment.

Role: Director, Product + Brand Activation
Mission: turn workflow automation from a generic tool category into a premium, owner-controlled execution layer while preserving n8n's core strengths.

This charter does not claim ownership of, endorsement by, or an official rebrand of n8n. It is a private test of how a re-positioned operating layer could be designed and implemented around n8n.

## Current external signal

n8n currently positions itself around flexible enterprise workflow automation, self-hosting, security/governance, Git-based control, workflow diffs, evaluations, monitoring and scalable execution. Lovable currently positions itself around rapidly building and shipping real applications, with authentication, data, integrations, hosting, security scanning and increasingly strong enterprise governance.

The strategic opportunity is to combine the strongest patterns without copying either brand:

- Lovable pattern: compress idea → working product → iteration.
- n8n pattern: connect systems → orchestrate workflows → govern execution.
- A11pro pattern: signal → decision → approval → execution → verification → evidence.

## Rebrand direction under test

Do not publicly rename n8n through this project.

Test a private product layer named:

**Execution Fabric**

Supporting language:
- operator-controlled workflows
- decision-to-execution infrastructure
- governed orchestration
- reversible execution
- evidence-backed operations
- commercial execution layer

Avoid:
- generic automation-platform language as the primary story
- inflated autonomous claims
- unsupported performance claims
- gratuitous use of "AI" in public-facing copy
- exposing internal vendor/tool names where they are not useful

## Layer-by-layer polish

### Layer 1 — Position

Input: business problem.
Output: explicit desired outcome, constraints, owner and evidence standard.

Acceptance:
- visitor understands what the system changes
- no vendor dependency is required to understand the value
- commercial outcome is concrete

### Layer 2 — Experience

Create a visual language based on:
- mineral dark surfaces
- electric cobalt action states
- restrained lime success signals
- oxide exception states
- flowing node geometry
- sharp editorial typography
- quiet motion
- dense but legible operator information

Acceptance:
- usable on iPhone
- one primary action per view
- state is visible without hunting
- destructive actions require explicit confirmation

### Layer 3 — Workflow

Canonical flow:

SIGNAL → DIAGNOSIS → PROPOSED ACTION → OWNER APPROVAL → EXECUTION → VERIFICATION → LEDGER

Acceptance:
- every material action has an owner/status
- failure produces a recoverable state
- no silent irreversible execution

### Layer 4 — Commercial

Connect the workflow layer to the Profit Engine:

DEMAND → CAPTURE → QUALIFY → CONVERT → DELIVER → RETAIN → EXPAND → MEASURE PROFIT

Acceptance:
- every commercial workflow can expose source, offer, segment, cost, revenue and evidence
- margin erosion creates a visible exception
- paid spend and live billing remain owner-controlled

### Layer 5 — Governance

Required controls:
- separate test and production
- credential isolation
- role-based access
- audit trail
- workflow versioning
- explicit approval boundary
- rollback/recovery path
- synthetic test data by default

Acceptance:
- a reviewer can reconstruct who approved what, when, why and what happened next

### Layer 6 — Verification

Each workflow must have:
- happy-path test
- failure-path test
- duplicate-event test
- timeout/retry test
- permission test
- data-integrity test
- rollback test
- evidence capture

Verification states:

UNVERIFIED → TESTING → PASSED → APPROVED → RELEASED

FAILED and BLOCKED are terminal states until repaired.

## Test matrix

| Test | PASS condition |
|---|---|
| Brand clarity | Operator understands value without vendor jargon |
| Mobile UX | Critical actions work on a phone |
| Workflow reliability | Test cases complete deterministically |
| Governance | No material action bypasses approval |
| Recoverability | Failed actions can be retried or rolled back |
| Evidence | Every material result has inspectable proof |
| Commercial utility | Workflow connects to measurable revenue/cost outcome |
| Margin protection | Variable delivery cost is visible |
| Reusability | Pattern can become an enterprise template |
| Security | Test credentials/data remain isolated |

## Implementation gate

Implement only after the test passes all critical controls.

If PASS:
1. preserve the test artifact
2. promote the terminology/design tokens into the private product layer
3. map production n8n workflows to the tested interaction model
4. connect to A11pro evidence and decision infrastructure
5. run staged production verification
6. keep rollback available
7. document the final release

If REVISE:
- retain the working parts
- change only the failed layer
- rerun the affected tests

If FAIL:
- do not promote the concept
- record failure evidence
- return to the smallest failing assumption

## 24-hour operating charter

This is an execution window, not a background timer.

Hour 0–2:
- establish terminology, design tokens and acceptance tests

Hour 2–6:
- test operator experience and workflow states

Hour 6–10:
- test governance, approval and failure recovery

Hour 10–14:
- test Profit Engine integration and evidence capture

Hour 14–18:
- test mobile usability, clarity and reusability

Hour 18–22:
- adversarial review of claims, controls and failure modes

Hour 22–24:
- promotion decision based on evidence

No claim of continuous unattended work is made. The window is a review/operating target that can be executed in active sessions.

## Promotion criteria

Promotion is evidence-based, not time-based.

Required before promotion:
- critical test cases pass
- no unresolved security/control blocker
- no unsupported public claims
- production boundary remains protected
- owner approval recorded
- rollback path documented
- commercial value can be measured

## Ownership

A11pro remains the control layer.

n8n, where used, is an execution/orchestration component rather than the public identity of the product.

Lovable, where used, is treated as a rapid application-building surface rather than the owner of the product strategy.

The product remains vendor-portable and owner-controlled.
