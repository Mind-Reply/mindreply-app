# Enterprise Visual Review Matrix

A result cannot advance because it looks polished. It advances only when presence, function, evidence, and deployment are all verified.

| Gate | Required evidence | Blocking failure |
|---|---|---|
| Distinctiveness | Route has its own composition, geometry, and interaction metaphor | Looks interchangeable with another platform or generic SaaS |
| Estate coherence | Shared material, type, motion, and authority grammar | Brand fragmentation or copied layout |
| Function | Every visible control has a tested outcome | Dead link, placeholder action, fake backend |
| Truth | Claims map to repository or deployment evidence | Unsupported production, security, or agent-state claim |
| Privacy | Local/network behavior is explicit; no secrets included | Hidden transmission or exposed token |
| Desktop | 1440px screenshot inspected individually | Overflow, overlap, weak hierarchy, unreadable density |
| Mobile | 390px screenshot inspected individually | Shrunk desktop, clipped controls, hover-only behavior |
| Keyboard | Logical tab order, visible focus, operable controls | Focus trap or invisible focus |
| Motion | State-driven, reduced-motion path present | Decorative perpetual motion or inaccessible animation |
| Build | Clean install/build/type result | Build failure or ignored error |
| Vercel | Real preview URL, project and deployment inspected | No preview, failed logs, wrong project/root |
| Rollback | Previous stable reference and rollback step recorded | Irreversible release path |
| Owner | Explicit approval recorded | Self-approval or automatic production release |

## Per-platform evidence package

Each child issue must contain:

1. v0 chat ID and preview URL.
2. Chosen direction and rejected alternatives.
3. Changed paths and implementation notes.
4. Interaction inventory with pass/fail results.
5. Desktop screenshot and inspection notes.
6. 390px screenshot and inspection notes.
7. Accessibility and reduced-motion notes.
8. Build/typecheck output.
9. Secret and public-claim review.
10. Vercel project, preview URL, and log result.
11. Rollback reference.
12. Owner decision.

## Current connection gate

v0 and Vercel must be connected through OAuth. Never substitute pasted personal tokens, screenshots of tokens, or committed environment files.
